# ADR-002: v0.6雨音は明示操作で開始する単一環境音から始める

- Status: Accepted
- Date: 2026年11月9日
- Revised: 2026年11月15日

## Context

次versionでは、Roomに「滞在したくなる感覚」を加えるため、雨音・環境音の導入を検討する。

Webを最初の公開先としているため、ブラウザのautoplay制約や、ユーザーが音を望まない環境を前提にする必要がある。

また、初回導入から複数環境音・BGM・細かな音量設定まで実装すると、MVPとして責務と検証範囲が急に大きくなる。

2026年11月9日の初回決定では、Webを含むAudio実装に `just_audio` を採用した。その後、同一のMP3とWAVを使ったFlutter Webスモークテストで、`just_audio` は両形式ともloop境界にごく短い途切れが発生した。一方、Web Audio APIの `AudioBufferSourceNode.loop` では、Chrome 156でMP3、WAVとも3周連続で自然にloopした。

この追加検証により、途切れは音声形式よりWeb上の再生方式に起因する可能性が高いと判断し、2026年11月15日にWeb版の再生方式を再決定した。

## Options considered

1. 起動時から自動で雨音を再生する
2. ユーザーの明示操作後に単一の雨音loopを再生する
3. 雨量・季節・場所ごとに複数環境音を最初から切り替える

Web版の再生方式については、追加で以下を比較した。

1. `just_audio` の `LoopMode.one` で再生する
2. Web Audio APIの `AudioBufferSourceNode.loop` で再生する

## Decision

v0.6.0では案2を採用する。

- 最初は単一の `rain_room_loop`
- Flutter Web版の音声再生にはWeb Audio APIの `AudioBufferSourceNode.loop` を使用する
- Web API連携には、現行Flutter / Dart環境で推奨される `package:web` と `dart:js_interop` を使用する
- 初回決定の `just_audio` 採用案は、追加スモークテストでMP3、WAVともloop境界に途切れが確認されたため置き換える
- app rootの `AmbientSoundProvider` が単一再生の状態とlifecycleを管理する
- `AmbientSoundRepository` がSharedPreferencesへbool設定を保存する
- `AmbientAudioService` がWeb Audio APIの詳細と音声リソースを管理する
- Web Audio APIの型と処理はService内に閉じ込め、ProviderやUIへ露出しない
- 配信用AssetはMP3 1種類とし、制作マスターのWAVは別途保管する
- 初期状態はOFF
- ユーザーの明示操作で再生開始
- 再生volumeは `1.0` 固定とし、音量は制作Assetを基準に調整する
- rain時のみ再生し、sunny時はON設定を維持したまま停止する
- ON / OFF設定は保存するが、Webでユーザーgestureなしの自動再開を前提にしない
- reload後に保存設定がONでも自動再生せず、再開待ちとする
- sunnyからrainへ変化した場合は再生を試行し、ブラウザに拒否された場合はON設定を維持して再開待ちとする
- RoomからLetter、Catalog、Bookshelfへ移動しても雨音を継続する
- browser tabがhiddenになった場合はpauseし、復帰時はON、rain、再開可能の条件を満たす場合に再生を試行する
- UI状態は `AmbientSoundUiState` の5状態として扱う
  - `off`
  - `playing`
  - `weatherPaused`
  - `resumeRequired`
  - `temporarilyPaused`
- 再開待ちで雨音ボタンを操作した場合はOFFへ切り替えず、再生を再試行する
- 雨音UIはRoom左上へ、標準Iconと文字を使った小型UIとして配置する
- volume slider、複数音源、BGM、雨量・季節・Furniture別の音声は同時導入しない
- iOS / Android版ではAudio実装を改めて評価し、v0.6.0ではモバイル用Serviceを先行実装しない

### Web Audio API実装の制約

- `AmbientAudioService` は単一の `AudioContext`、デコード済み `AudioBuffer`、最大1つの再生中SourceNodeを管理する
- MP3の読み込みと `decodeAudioData` をServiceが管理し、同じ音源の再生ごとに再デコードしない
- `AudioBufferSourceNode` は停止後に再利用せず、再生または再開のたびに新しく生成する
- 新しいSourceNodeを開始する前に既存SourceNodeを停止・切断し、二重再生を防止する
- アプリ上のpauseは、現在のSourceNodeを停止・破棄することを指す。resumeは新しいSourceNodeを `loopStart = 0` から開始することを指し、停止位置の保存・復元は行わない
- `AudioContext.resume()` はブラウザのautoplay制限を考慮し、ユーザー操作から直接試行する。拒否された場合はON設定を維持して `resumeRequired` とする
- 非同期のAsset読み込み・decode中にWeather変更、OFF操作、別の再生要求、disposeが発生した場合は、古い処理の完了後に再生を開始しない
- OFF、rain以外への変化、disposeでは進行中の再生要求を無効化し、SourceNodeを停止・切断する
- Serviceは再生開始成功、停止、再生拒否、読み込み・decode失敗をProviderへ通知できる構成とする
- Provider上の `playing` は可聴再生そのものと同義とせず、Serviceの開始結果、app visibility、weatherを組み合わせてUI状態を決定する

## Rationale

- Webのautoplay制約と相性がよい
- 音を望まない利用環境でも操作を妨げない
- 一つの音源で体験価値を検証できる
- 「雨音を主役にする」というサウンド方針と一致する
- BGMや多種類SEを先に増やさずMVPを維持できる
- app rootで単一の再生状態を管理することで、既存の画面遷移構造を変えずにLetterを読む時間にも雨音を継続できる
- Provider、Repository、Serviceの責務を限定し、保存処理とWeb固有のAudio実装を既存UIから分離できる
- MP3 1種類に限定することで、Web配信サイズとブラウザ互換性を優先できる
- 同一素材の比較で、`just_audio` ではMP3、WAVとも途切れ、Web Audio APIでは両形式とも自然にloopした
- Web Audio APIでMP3とWAVの聴感差が確認されなかったため、配信用MP3と制作マスターWAVの分離を維持できる

## Consequences

### Positive

- 実装・テスト範囲を小さくできる
- ユーザー操作と音声再生の因果が明確になる
- 音源品質そのものを評価しやすい
- Chrome 156の検証では、配信用MP3を維持したまま自然なloop再生ができる
- 既存のWeather overrideを含む `effectiveWeather` と同じ条件で雨音を制御できる
- 既存のSharedPreferencesデータを変更せず、独立したbool設定を追加できる
- Web固有の処理をService内に閉じ込めるため、Provider、Repository、UI状態モデルを維持できる

### Negative

- preferenceがONでも、Webでは訪問直後から必ず自動再生できるとは限らない
- sunnyからrainへの変化時やtab復帰時も、ブラウザによって再生が拒否され、再開操作が必要になる場合がある
- Provider上の `playing` がtrueでも、端末音量、tab mute、AudioContextの状態などにより実際には聞こえない場合がある
- Web Audio APIでは音声全体をdecodeして保持するため、圧縮Assetのファイルサイズとは別にAudioBufferのメモリを使用する
- 非同期の読み込み・decodeとWeather、OFF、disposeの競合をService内で明示的に扱う必要がある
- loop品質の追加検証はChrome 156であり、他のブラウザは本番前または対応対象へ追加するときに確認が必要になる
- 雨量や季節による音の変化は初期versionでは表現しない
- 雨音のON / OFF UIはRoomにのみ置くため、Letter、Catalog、Bookshelf表示中に切り替えるにはRoomへ戻る必要がある
- iOS / Android用のAudio実装はこの決定に含まれず、対応時に再評価が必要になる

## Revisit when

- 単一雨音でのユーザーテスト結果が得られた
- 晴れ・雪など天候別の環境音が必要になった
- BGMや効果音を追加する
- iOS / Android版を本格的に実装する
- Chrome以外のブラウザを正式な対応対象に追加する
- Web Audio APIでブラウザ固有のloop、decode、lifecycle問題が確認された
- Letter、Catalog、Bookshelf表示中にも音声操作が必要になった
- volume sliderや複数音源を求める具体的な利用結果が得られた
